**ПЛАТФОРМА «РЕАЛ ХОЛАТ» — ТЕХНИЧЕСКОЕ ЗАДАНИЕ**

---

**АРХИТЕКТУРА ДАННЫХ**

Система оперирует четырьмя сущностями: школа, обещание, проверка, пользователь.

Школа: название, адрес, координаты, фото, район, список привязанных камер, текущий статус захвата (0-100%), цвет на карте, количество активных игроков в радиусе.

Обещание: привязано к школе. Содержит: описание работ, источник (etender или crowdsourced), дедлайн, сумма контракта (если есть), тип (капитальный или расходник), автоматически сгенерированный чеклист, текущий статус в воронке, timestamp создания.

Проверка: привязана к обещанию и пользователю. Содержит: фото (stripped EXIF), ответы чеклиста, комментарий, timestamp создания, timestamp публикации (отложенный), результат камерной валидации (подтверждено/не подтверждено/камера недоступна), результат классификатора, баллы начисленные.

Пользователь: ID, привязанная школа, район, стрик (текущий и максимальный), баллы (текущий сезон и всего), история проверок, streak freeze (количество доступных).

---

**ПАЙПЛАЙН 1: ПОСТУПЛЕНИЕ ОБЕЩАНИЙ**

*Автоматический канал.*

Шаг 1\. Парсер обращается к etender.uzex.uz по расписанию (раз в сутки). Фильтрует тендеры по категориям, связанным с образовательной инфраструктурой: ремонт, строительство, оборудование, мебель.

Шаг 2\. Из тендера извлекаются: объект (школа), описание работ, сумма, дедлайн исполнения, подрядчик. Школа матчится с базой школ по названию и адресу.

Шаг 3\. По описанию работ генерируется чеклист проверки. Для демо — ручной маппинг по 10 категориям (ремонт санузла → унитазы заменены? плитка новая? дозаторы установлены?). Для масштаба — LLM парсит ТЗ тендера и генерирует чеклист автоматически.

Шаг 4\. Обещание создаётся в статусе «ожидает дедлайна». По наступлении дедлайна статус переключается на «открыто для проверки». Все пользователи, привязанные к этой школе, получают push-уведомление.

*Crowdsourced канал.*

Шаг 1\. Гражданин создаёт обещание вручную: выбирает школу, описывает что обещано, указывает источник (объявление, встреча, пост в Telegram, фото объявления).

Шаг 2\. Обещание попадает в статус «требует подтверждения». Другие пользователи, привязанные к этой школе, видят запрос на подтверждение.

Шаг 3\. После N подтверждений (для демо — 3\) обещание переходит в статус «подтверждено» и становится доступным для проверки. Чеклист формируется из описания автором \+ дополнений от подтверждающих.

**ПАЙПЛАЙН 2: ПРОВЕРКА ГРАЖДАНИНОМ**

Шаг 1\. Пользователь открывает карту. Видит школы района. Цветовая кодировка: яркая зелёная — свежий захват, всё ок. Яркая красная — свежий захват, выявлены проблемы. Тусклая — захват деградирует, давно не проверялась. Серая — никогда не проверялась. Рядом с каждой школой — текущий множитель баллов (обратно пропорционален плотности игроков).

Шаг 2\. Пользователь нажимает на школу. Видит список обещаний со статусами. Видит текущий захват: «2/3 захвачено. Зона санитарии деградирует через 2 дня. Зона оборудования — серая.»

Шаг 3\. Пользователь нажимает «Проверить» на конкретном обещании. Открывается камера приложения (не галерея). Делает фото. Заполняет чеклист: каждый пункт — да/нет/не могу оценить. Комментарий опционально. Нажимает «Отправить».

Шаг 4\. Клиент стрипает EXIF из фото, отправляет на сервер вместе с: ID обещания, ответами чеклиста, timestamp, геолокацией устройства.

Шаг 5\. Сервер принимает отчёт. Запускается камерная валидация (пайплайн 3). Отчёту присваивается случайный delay публикации (12-72 часа). Отчёт сохраняется в статусе «обрабатывается».

Шаг 6\. Пользователю возвращается немедленный feedback: «Записано. Захват: \+1/3 школы. \+N баллов (с учётом множителя района и стрика). Стрик: X дней. Появится на дашборде через 24-72 часа.»

**ПАЙПЛАЙН 3: КАМЕРНАЯ ВАЛИДАЦИЯ**

*Режим кросс-валидации (при каждой проверке).*

Шаг 1\. Сервер получает отчёт с timestamp и геолокацией. Запрашивает видеопоток школьных камер за окно ±5 минут от timestamp отчёта.

Шаг 2\. Система сопоставляет: геолокация устройства в пределах 200м от школы? На видео с камеры виден человек с телефоном в соответствующей зоне в соответствующее время? Совпадение не обязано быть идеальным — достаточно подтверждения присутствия человека в здании школы.

Шаг 3\. Результат: подтверждено / не подтверждено / камера недоступна. Если подтверждено — отчёт проходит в следующую стадию. Если не подтверждено — отчёт помечается как «не верифицирован», не публикуется на дашборде, пользователь не получает баллы за захват. Если камера недоступна — отчёт принимается с пометкой «без камерной валидации», недоступность камеры генерирует отдельный алерт.

Шаг 4\. Фото из подтверждённого отчёта идёт на классификатор. Для демо — ручная категоризация. Для масштаба — image classification модель, обученная на категориях: ремонт выполнен / частично выполнен / не выполнен.

*Режим автоматического мониторинга (по расписанию).*

Шаг 1\. Для каждого обещания типа «капитальный» с наступившим дедлайном система делает snapshot с камер школы.

Шаг 2\. Сравнивает с baseline snapshot, сделанным до дедлайна (или при создании обещания). Image diff: если визуальных изменений нет (порог определяется эмпирически) — автоматический флаг «ремонт не обнаружен».

Шаг 3\. Флаг отображается на дашборде. Если совпадает с негативными отчётами граждан — confidence проблемы повышается. Если граждане говорят «ремонт сделан», а камера не видит изменений — система помечает противоречие для ручной проверки.

*Мониторинг работоспособности камер.*

Статичная картинка дольше 30 минут → алерт «камера заблокирована». Потеря сигнала → алерт «камера отключена». Резкое изменение угла → алерт «камера перенаправлена». Все алерты отображаются на дашборде как отдельная категория: «вмешательство в инфраструктуру мониторинга».

**ПАЙПЛАЙН 4: ТЕРРИТОРИАЛЬНЫЙ ЗАХВАТ И SCORING**

*Расчёт баллов.*

Базовые баллы за зону \= 10\. Множитель плотности \= 1 / (количество активных игроков в радиусе 1км от школы \+ 1). Если 0 игроков — множитель 1.0 (10 баллов). Если 9 игроков — множитель 0.1 (1 балл). Множитель стрика: дни 1-6 — x1.0. Дни 7-13 — x1.5. Дни 14-29 — x2.0. Дни 30+ — x3.0. Итоговые баллы \= базовые × множитель плотности × множитель стрика.

*Дробный захват.*

Каждая школа имеет N зон проверки (определяется количеством обещаний). Проверка одной зоны \= захват 1/N школы. Индикатор захвата на карточке школы показывает общую долю: 0/3, 1/3, 2/3, 3/3. Полный захват (все зоны) даёт бонус x1.5 к баллам за последнюю зону.

*Деградация.*

Тип «расходник» (мыло, бумага, расходные материалы): деградация через 3 дня. Тип «капитальный» (ремонт, оборудование, мебель): деградация через 30 дней. Деградация поэтапная: 100% → 75% (визуально чуть тускнее) → 50% (заметно тусклая) → 25% (почти серая) → 0% (серая, свободна для захвата). При деградации до 50% — push-уведомление привязанным пользователям: «Школа №45 нуждается в повторной проверке». При деградации до 0% — школа появляется в ленте «доступные для захвата» с повышенным множителем (x1.3 к обычному).

*Leaderboard.*

Районный рейтинг: все пользователи района ранжированы по баллам текущего сезона. Нормализация: баллы не абсолютные, а «баллы на одну доступную школу в районе», чтобы районы с 50 школами и районы с 10 школами были сопоставимы. Сезон \= учебная четверть. В конце сезона — итоговый рейтинг, баллы обнуляются, стрик сохраняется.

**ПАЙПЛАЙН 5: СТАТУСНАЯ ВОРОНКА И ЭСКАЛАЦИЯ**

Каждое обещание проходит через воронку:

«Ожидает дедлайна» → «Открыто для проверки» → «Проверено гражданами» → «Верифицировано камерой» → «Передано ответственному» → «В работе» → «Решено».

Переходы: «Ожидает дедлайна» → «Открыто для проверки» — автоматически по наступлении дедлайна. «Открыто для проверки» → «Проверено гражданами» — автоматически после первого верифицированного отчёта. «Проверено гражданами» → «Верифицировано камерой» — автоматически при успешной камерной валидации. Последующие переходы — ручные (для демо захардкожены, для масштаба — интеграция с системой управления обращениями).

Каждый переход → push-уведомление автору отчёта. Пользователь видит прогресс своего отчёта.

Эскалация: если статус не меняется 14 дней после перехода в «верифицировано камерой» → обещание автоматически получает метку «игнорируется». Метка «игнорируется» → обещание попадает в еженедельный Telegram-отчёт. Метка «игнорируется» → рейтинг района снижается на фиксированное значение за каждое игнорируемое обещание. Через 30 дней без реакции → метка «критическое игнорирование», выделяется на дашборде красным.

**ПАЙПЛАЙН 6: ПУБЛИЧНЫЙ ДАШБОРД**

*Гражданский вид (главный экран).*

Карта Ташкента с школами. Цвета по статусу захвата и состоянию. Фильтры: район, тип обещания, статус. Общая статистика: всего школ на платформе, проверено за эту неделю, процент выполненных обещаний, количество активных инспекторов. Лента последних проверок (агрегированная, без имён): «Школа №45: 4 гражданина проверили санитарию. 3 из 4 сообщают о проблеме.»

*Районный вид.*

Рейтинг районов: отсортированы по проценту выполненных обещаний. Каждый район: количество школ, проверено/не проверено, процент выполнения, количество игнорируемых обещаний, изменение за неделю (рост/падение).

*Вид школы.*

Карточка: название, адрес, фото, привязанные обещания. Каждое обещание: источник, дедлайн, текущий статус в воронке, агрегированный результат проверок (N проверили, X% говорят выполнено), визуальный индикатор захвата. Без индивидуальных отчётов. Без имён. Только агрегат.

*Telegram-канал.*

Автоматическая публикация раз в неделю. Содержание: топ-5 школ с наибольшим количеством нерешённых проблем. Топ-3 района по падению рейтинга. Количество новых проверок за неделю. Количество обещаний в статусе «игнорируется». Общий процент выполнения по городу.

**ПАЙПЛАЙН 7: ГЕЙМИФИКАЦИЯ — ПОЛНЫЙ ЦИКЛ**

*Ежедневный цикл.* Пользователь получает утреннее уведомление: «Школа №45: зона санитарии деградирует завтра. Проверь сегодня — \+15 баллов и стрик продолжится.» Проверяет одну зону — стрик растёт, баллы начисляются, захват обновляется.

*Еженедельный цикл.* Каждую пятницу — итоги недели: «Ты проверил 3 школы. Твой район поднялся на 2 позиции. Ты на 7-м месте в районном рейтинге.» Streak freeze зарабатывается: 50 баллов \= 1 freeze. Используется автоматически при пропуске дня.

*Сезонный цикл (учебная четверть).* Начало сезона: новые цели, обнуление баллов, сохранение стрика. Battle pass трек: проверить 10 школ (бейдж «Начинающий инспектор»), обнаружить 5 проблем (бейдж «Зоркий глаз»), держать стрик 30 дней (бейдж «Несокрушимый»), попасть в топ-10 района (бейдж «Районный страж»). Конец сезона: итоговый лидерборд, лучшие инспекторы выделены на дашборде.

*Milestones (бессрочные).* 10 проверок — «Активный гражданин». 50 проверок — «Районный инспектор». 200 проверок — «Городской страж». Каждый milestone — permanent badge в профиле и повышенный вес отчётов в агрегации (trusted verifier).
